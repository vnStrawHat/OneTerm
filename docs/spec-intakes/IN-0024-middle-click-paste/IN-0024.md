# Spec Intake: Middle-click paste

ID: IN-0024
Date: 2026-09-11
Type: new_spec
Lane: normal

## Source

Owner request (2026-09-11): add "middle-click paste"; add a "middle-click paste" setting to
Terminal Settings, default on; the feature must respect that setting.

## Requested Outcome

A middle-button press on the terminal grid pastes the clipboard exactly as Ctrl+Shift+V /
the context-menu Paste does (same sanitising, bracketed-paste, broadcast fan-out, and error
toast). Terminal Settings › Mouse gains a "Middle-Click Paste" switch, on by default and
persisted in `terminal.json` under the `mouse` group; when it is off, the middle button
behaves as today (forwarded to a program in mouse mode, otherwise ignored). A program that
enabled mouse reporting receives the middle click instead of a paste unless Shift is held,
the same override alacritty and xterm use.

## Project Impact

- Surfaces: terminal grid (middle button), Settings › Terminal › Mouse (new switch).
- Contracts: `terminal.json` `mouse.middle_click_paste` (additive, default `true`);
  `TerminalSession` gains `is_mouse_mode()` (public contract, additive; both backends share
  the macro implementation, the test fake follows).
- Users: a new default behaviour on middle click; anyone relying on the middle button
  reaching a non-mouse-mode program (nothing reached it before) is unaffected.
- Safety: paste already goes through the sanitising `paste` path of `crates/terminal`; a
  middle click while a member of a broadcast channel fans the paste out like any paste.

## Architecture and Boundary Questions

- Runtime and owning boundary: `crates/terminal-view` decides (mouse state machine returns a
  `Paste` outcome, the view runs the existing `paste_clipboard`); `crates/settings` owns the
  field; `crates/settings-ui` owns the switch; `crates/terminal` exposes mouse mode.
- Data ownership and lifecycle: `TerminalSettings.middle_click_paste` mirrors
  `MouseConfig.middle_click_paste`, saved with the rest of `terminal.json`.
- Auth, security, privacy, or audit: none beyond the existing paste policy.
- External systems and side effects: clipboard read (already done by paste).
- Public interfaces and compatibility: old `terminal.json` files load with the default `true`.
