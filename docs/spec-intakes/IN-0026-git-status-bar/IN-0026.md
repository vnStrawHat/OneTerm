# Spec Intake: Git status in the status bar

ID: IN-0026
Date: 2026-09-11
Type: new_spec
Lane: normal

## Source

Owner request (2026-09-11): add git status to the status bar.

## Requested Outcome

The status bar shows the git state of the active local terminal's working directory next to
the breadcrumb: the current branch (or the short commit id when detached), a `*` when the
work tree or index has changes, and the ahead/behind counts against the upstream. The
indicator is hidden when the active terminal is an SSH session, has no cwd yet, the cwd is
not inside a git repository, or `git` is not installed.

## Project Impact

- Surfaces: status bar (new indicator after the breadcrumb).
- Contracts: `ActiveTerminalMetricsProvider` gains a `local_cwd` extractor (additive; the
  terminal feature keeps contributing it at init).
- Users: no new setting; the indicator appears whenever a local shell sits in a repository.
- Side effects: `git status --porcelain=v2 --branch` runs in the background at most every 2 s
  for the active cwd, with `GIT_OPTIONAL_LOCKS=0` so it never takes the index lock away from
  the user's own git commands.

## Architecture and Boundary Questions

- Runtime and owning boundary: `crates/terminal-view` exposes the local cwd of the active
  panel through the existing provider seam; `crates/workspace/src/widgets/git_status.rs`
  polls git on the background executor and formats the label. The shell stays
  feature-agnostic (no `TerminalPanel` dependency).
- Data ownership and lifecycle: nothing persisted; the last label lives in the widget.
- Auth, security, privacy, or audit: git is spawned with `-C <cwd>` only; no user input is
  interpolated into arguments. Output is parsed, never rendered raw.
- External systems and side effects: spawns the `git` binary found on `PATH`; on Windows the
  child gets `CREATE_NO_WINDOW` so no console flashes.
- Public interfaces and compatibility: additive provider field; the service test fixture
  gains the same field.
