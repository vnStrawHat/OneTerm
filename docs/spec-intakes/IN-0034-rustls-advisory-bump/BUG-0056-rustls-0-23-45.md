not reach any terminal or file-transfer path — only the auto-updater's HTTPS client.

The advisory's own remedy (`>= 0.23.45`) is a patch release inside `^0.23`, which is what every
dependant requires, so step (a) of the fix ladder applies and steps (b) and (c) are not needed.

### Evidence

- Advisory: RUSTSEC-2026-0285 / GHSA-2mjx-qc3c-rqvc. rustls accepted a TLS 1.3 handshake
  message sent at the wrong encryption level when it followed a key-changing message in the
  same record (for example a plaintext `EncryptedExtensions` packed into the `ServerHello`
  record), where RFC 8446 section 5.1 requires an `unexpected_message` alert. The handshake
  transcript stays authenticated, so a network-position attacker cannot alter or complete a
  handshake with it. Affected `< 0.23.45`; patched `0.23.45`.
- Fix ladder step taken: (a). `cargo update -p rustls --dry-run` and `--precise 0.23.45`
  produce the same plan, so `0.23.45` is both the patched release and the newest `0.23.x`;
  every dependant requires `^0.23`, so nothing needed a dependant bump (step b) and no
  `deny.toml` ignore entry was added (step c). **Nothing here is deferred.**
- Blast radius: `Cargo.lock` 8 lines, `THIRD-PARTY-NOTICES.md` 2 lines. No manifest, no
  `deny.toml`, no source file.
