# Spec Intake: rustls advisory RUSTSEC-2026-0285 fails cargo-deny

ID: IN-0034
Date: 2026-09-14
Type: maintenance
Lane: normal

## Source

CI report (2026-09-14): the `cargo-deny` job on `main` is red. `cargo deny check advisories`
reports `error[vulnerability]` for `rustls 0.23.40` — RUSTSEC-2026-0285, "TLS 1.3 handshake
messages incorrectly accepted across encryption level boundaries"
([advisory](https://rustsec.org/advisories/RUSTSEC-2026-0285),
[announcement](https://github.com/rustls/rustls/security/advisories/GHSA-2mjx-qc3c-rqvc)).
Solution named by the advisory: upgrade to `>= 0.23.45`.

rustls does **not** enter the graph through `russh`: OneTerm's SSH stack uses russh's `ring`
backend and no TLS. The single path is the auto-updater's HTTPS client:

```text
rustls 0.23.40
├── hyper-rustls 0.27.9 → reqwest 0.12.28 → oneterm-update → oneterm-app / oneterm-settings-ui
├── reqwest 0.12.28 (*)
└── tokio-rustls 0.26.4 → hyper-rustls / reqwest (*)
```

## Requested Outcome

`cargo deny check licenses bans advisories` is green again, with the smallest safe change and
no semver-incompatible dependency movement.

## Project Impact

- Surfaces: the auto-updater's TLS client (`crates/update`), release-manifest and artifact
  downloads. No SSH/SFTP surface — those never touch rustls.
- Contracts: none. `reqwest`'s workspace requirement (`0.12`, feature
  `rustls-tls-native-roots`) is unchanged; only the resolved `Cargo.lock` patch version moves.
- Generated artifacts: `THIRD-PARTY-NOTICES.md` is derived from `Cargo.lock` and must be
  regenerated (`python scripts/third-party-notices.py --check` is a CI gate).

## Architecture and Boundary Questions

- Runtime and owning boundary: transitive dependency of `crates/update` only; no OneTerm code
  calls rustls directly.
- Data ownership and lifecycle: none.
- Auth, security, privacy, or audit: security-relevant — a TLS protocol-conformance fix. The
  practical effect of the bug is that a peer could send handshake messages in plaintext that
  should have been encrypted; the transcript stays authenticated, so it does not let a
  network attacker alter or complete a handshake.
- External systems and side effects: the update server over HTTPS.
- Public interfaces and compatibility: none. `0.23.40 → 0.23.45` is a patch bump inside the
  `^0.23` requirement every dependant already states.
