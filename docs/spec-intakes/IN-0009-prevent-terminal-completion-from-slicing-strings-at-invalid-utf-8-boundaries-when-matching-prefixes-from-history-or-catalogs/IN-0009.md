# Spec Intake: Prevent terminal completion from slicing strings at invalid UTF-8 boundaries when matching prefixes from history or catalogs.

ID: IN-0009
Date: 2026-08-14
Type: maintenance
Lane: tiny

## Source

A OneTerm 0.3.9 Windows x86_64 release crash report records a main-thread panic at `crates/completion/src/history.rs:169:25`: `end byte index 1 is not a char boundary; it is inside '❯' (bytes 0..3 of string)`.

## Requested Outcome

Prevent terminal completion from slicing strings at invalid UTF-8 boundaries when matching prefixes from history or catalogs.

## Project Impact

The change is localized to the gpui-free completion engine's shared prefix matcher. History and catalog candidates may contain Unicode while the typed prefix has a different UTF-8 byte width. Such inputs must be treated as non-matches rather than terminating OneTerm. Matching rules, ranking, history ownership, persistence, and UI behavior remain unchanged.
