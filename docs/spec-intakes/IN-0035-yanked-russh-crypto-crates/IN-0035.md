# Spec Intake: cargo-deny warns on yanked chacha20 and der under russh

ID: IN-0035
Date: 2026-09-15
Type: maintenance
Lane: normal

## Source

Owner report (2026-09-15), confirmed on `main` @ `c6e2bd8`: `cargo deny check advisories`
ends `advisories ok` but emits two `warning[yanked]` entries. Both crates enter the graph only
through the `russh` family's release-candidate crypto stack:

```text
chacha20 0.10.1  (Cargo.lock:93)
|-- rand 0.10.1 -- internal-russh-num-bigint 0.5.0 -- russh 0.61.2 -- oneterm-ssh / oneterm-tools
|                  pageant 0.2.1 -- russh 0.61.2
|                  (rand is also a direct workspace dependency of oneterm-app / oneterm-tools)
`-- ssh-cipher 0.3.0-rc.9 -- ssh-key 0.7.0-rc.10 -- russh 0.61.2

der 0.8.0  (Cargo.lock:146)
`-- ecdsa 0.17.0-rc.18 / pkcs1 0.8.0-rc.4 / pkcs5 0.8.0 / pkcs8 0.11.0 / sec1 0.8.1 / spki 0.8.0
    -- p256 / p384 / p521 0.14.0-rc.10, rsa 0.10.0-rc.18, ed25519-dalek 3.0.0-rc.0,
       elliptic-curve 0.14.0-rc.33, ssh-key 0.7.0-rc.10 -- russh 0.61.2
```

`BUG-0056` (IN-0034) left these two open and predicted that clearing them "needs a russh
dependency-family bump". That prediction no longer holds: both crates have since published
non-yanked patch releases inside the ranges russh already requires.

## Requested Outcome

`cargo deny check licenses bans advisories` runs with zero `warning[yanked]` lines, using the
smallest safe change.

## Project Impact

- Surfaces: SSH/SFTP only (`crates/ssh`, and `crates/sftp-ui` through `oneterm-ssh`), plus
  `crates/tools`. `chacha20` backs the ChaCha RNG inside `rand` and the `chacha20-poly1305`
  SSH cipher inside `ssh-cipher`; `der` backs every ASN.1 key and certificate decode on the
  public-key authentication and host-key paths.
- Contracts: none if the fix stays at lock level. `russh = "0.61"` and `russh-sftp = "2.3"` in
  `[workspace.dependencies]` are unchanged.
- Generated artifacts: `THIRD-PARTY-NOTICES.md` is derived from `Cargo.lock` and is a CI gate.

## Architecture and Boundary Questions

- Runtime and owning boundary: transitive dependencies of `russh`; no OneTerm source names
  either crate. `rand` is a direct workspace dependency but only pulls `chacha20` as its RNG.
- Data ownership and lifecycle: none.
- Auth, security, privacy, or audit: security-adjacent. `der` decodes private keys, public keys
  and host keys; `chacha20` is a transport cipher and an RNG backend. Neither yank is a RustSec
  advisory (`cargo deny` already reports `advisories ok`), and neither patch release changes an
  API OneTerm calls, so the risk lane stays normal.
- External systems and side effects: SSH servers; wire behaviour unchanged.
- Public interfaces and compatibility: none. Both moves are patch releases inside the `^0.10`
  and `^0.8` requirements every dependant already states.
