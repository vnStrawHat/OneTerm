# Spec Intake: hotpath profiling

ID: IN-0046
Date: 2026-09-25
Type: change_request
Lane: normal

Document number: 46.

## Source

Owner request, 2026-09-25: "try the `hotpath` profiler to optimize CPU and memory
further." Crate: `hotpath` 0.26.1 on crates.io (MIT, <https://github.com/pawurb/hotpath-rs>).
Follows `IN-0045` (memory usage review), which attributed memory by counter and region
but not by function.

## Requested Outcome

- A developer-only way to profile OneTerm's hot paths by function, for time and for
  allocations, that adds nothing to a normal build.
- Measurements under four loads: idle, a 300k-line flood, two tabs of a coding-agent-like
  TUI, and an SFTP download of many small files.
- A ranked list of optimization candidates with expected gains. No optimization is
  implemented under this intake's first packet.

Evidence: [`research/hotpath-evaluation.md`](research/hotpath-evaluation.md).

## Project Impact

- Surfaces: none at runtime. Build surface: a new optional workspace dependency and one
  `hotpath-profiling` feature in `oneterm-app`, `oneterm-terminal-view`,
  `oneterm-terminal`, `oneterm-vt`, `oneterm-highlight`, `oneterm-local-shell` and
  `oneterm-ssh`, plus `hotpath-profiling-alloc` in `oneterm-app`.
- Contracts: `oneterm-vt` is an external contract (`docs/PROJECT.md`). The new feature is
  default-off, adds one optional dependency, and changes no public item; the
  `--no-default-features` promise is unchanged.
- The OOM allocator (`crates/app/src/oom.rs`) stays the process allocator in every build;
  the allocation build wraps it.

## Candidate Work Packets

- [x] [`US-0142`](US-0142-hotpath-feature.md) — the `hotpath-profiling` feature and its

Optimization candidates, ranked ([`research/hotpath-evaluation.md`](research/hotpath-evaluation.md)
§ 5). Not created; ids reserved.

- [x] [`US-0143`](US-0143-row-reuse.md) — **The history row dropped at the limit is reused
  for the next new row** (`oneterm-vt`). Done: 0 allocations per scrolled line,
  `Parser::advance` -26 % in the flood (measured). One 715 B row allocation per scrolled line today (300k per 300k-line
  flood, 181k per 3-min TUI). Expected: -1 alloc/-1 free per line, `Parser::advance` -5 to
  -10 % (estimate). S, low-medium risk. Cheap and safe. No dependencies.
- [ ] `US-0144` — **The highlight scanner reuses its per-line buffers** (`chars`,
  `byte_to_char`; ASCII lines skip the map). 4 allocations and 1.3 KB per scanned line
  today, the largest attributed bytes in the TUI load (170 MB per run). Expected: -3 to -4
  allocations per line, -10 to -20 % scan time (estimate). S, low risk. Cheap and safe.
- [ ] `US-0145` — **Attribute, then cut, the UI thread's work outside the terminal
  element.** About 80 % of the UI thread's CPU (idle 2.4 %, TUI 6.0 %, flood 16.6 % of a
  core) and about 2,500 allocations per frame are outside every site. First step: sites on
  the workspace, dock, panel and status-bar renders; then view caching and a cursor-only
  blink repaint. M, medium risk. Needs a decision after that measurement.
- [ ] `US-0146` — **Plain ASCII runs skip text shaping** (per-glyph cache, positions from
  the grid, ligatures off). Flood: 46 % of `PlanCache::update`. Agent TUIs: small. M-L,
  medium-high risk. Needs a decision.
- [ ] `US-0147` — **The PTY owner loop pays less per ConPTY chunk.** About 7 us of thread
  CPU per chunk against 1.3 us of parse under line-per-write output. First step: sites on
  the loop's lock, notify and poll. M, medium risk (latency). Needs a decision.

## Architecture and Boundary Questions

- Runtime and owning boundary: the guard lives in `oneterm_app::run`; sites live in the
  crates that own the code.
- Data ownership and lifecycle: measurements are in-process and written once at exit.
- Auth, security, privacy, or audit: hotpath's metrics server listens on port 6770 while
  a profiling build runs. It is never in a shipped build. `HOTPATH_METRICS_SERVER_OFF=1`
  turns it off.
- External systems and side effects: none.
- Public interfaces and compatibility: `oneterm-vt` gains a default-off feature and no
  public item.
