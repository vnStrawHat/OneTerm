# Spec Intake: SSH keepalive and disconnect visibility

ID: IN-0013
Date: 2026-08-21
Type: new_spec
Lane: high_risk

## Source

User follow-up after investigating an apparently hung SSH terminal on OneTerm 0.4.2. The user confirmed Ctrl+S/Ctrl+Q are consumed by configured key bindings and requested both configurable keepalive and visible closed-session behavior.

## Requested Outcome

Make SSH keepalive configurable for newly opened sessions and make closed SSH sessions visibly persistent and non-interactive while preserving access to prior terminal output.

## Project Impact

- Adds an additive `ssh` group to the `terminal.json` schema owned by `oneterm-settings`.
- Adds an SSH group to the Terminal settings page.
- Passes a validated keepalive policy through `SessionFactory` into `oneterm-ssh`; existing sessions are unchanged.
- Changes the terminal-view lifecycle presentation for remotely closed SSH sessions without changing local-shell exit presentation.
- Preserves credentials, host-key checks, terminal output, selection, copy, scroll, and search behavior.

## Architecture and Boundary Questions

- Runtime and owning boundary: persisted values belong to `oneterm-settings`; the runtime policy crosses the existing `SessionFactory` boundary and is consumed only by `oneterm-ssh`.
- Data ownership and lifecycle: missing settings retain the 0.4.2 behavior (`enabled = true`, `interval = 30 seconds`); changes apply only to new connections.
- Auth, security, privacy, or audit: no credential, authentication, host-key, or secret behavior changes.
- External systems and side effects: enabling keepalive sends SSH keepalive requests at the configured interval; disabling it restores russh's no-keepalive behavior.
- Public interfaces and compatibility: `SessionFactory::connect_ssh` gains one runtime-policy argument; first-party implementations and test doubles must be updated together.
