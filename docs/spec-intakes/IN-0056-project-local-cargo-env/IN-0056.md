## Source

Owner request, 2026-10-23: review `D:\TrungKFC-Research\Rust\Claude-Rust-Template` (a Claude Code Rust workspace template) and adopt what applies to OneTerm. Of the eight items listed, the owner ruled:

- 1-4 apply: a SessionStart hook that confines temp files and caps `CARGO_BUILD_JOBS` with a disk-space warning; `.worktreeinclude`; `debug = false` for third-party crates in `profile.dev`; a hook fallback line in every agent prompt.
- 5 apply, report if the clobber recurs: one `CARGO_TARGET_DIR` for the main checkout and every worktree.
- 6 apply, low benefit accepted: `CARGO_HOME` inside the project.
- 7 (`.gitattributes` global LF) and 8 (split the long agent docs) are deferred to their own work.

Not adopted (already present or conflicting): the toolchain, rustfmt and editorconfig files; the `unsafe_code`, `unwrap_used`, `expect_used`, `print_stdout` lints; thin LTO; disabling the PowerShell tool; the cargo permission allowlist; the template's agents and workflow.

## Requested Outcome

Every Bash call in a Claude Code session on this repository, including subagents in `.claude/worktrees/*`, builds into the root `target/`, caches the registry in the root `.cargo-home/`, writes temp files into the root `.tmp/`, and runs no more parallel rustc processes than the machine's RAM allows. Third-party crates carry no debuginfo in dev builds.

## Project Impact

Build environment only; no product behaviour. The shared target reverses the standing rule "never point a worktree agent at the main checkout's target" (docs/agents/subagent-workflow.md, memory): the owner accepts the risk and wants the clobber symptoms reported if they recur.
