# Spec Intake: Duplicate sessions into empty Spaces

ID: IN-0006
Date: 2026-08-12
Type: new_spec
Lane: normal

## Source

User-approved product request, clarified in conversation on 2026-08-12:

- Replace the single-destination **Duplicate Session** command with a destination submenu.
- Keep **In New Tab** as the existing/default destination.
- When the current tab has empty Spaces, show one **Into Space #N** item per empty Space directly below **In New Tab**; show no such items when none are empty.
- Keep **Split Right** and **Split Down** below a separator.
- Show the matching **Space #N** label inside every empty Space so the destination is visually identifiable.

## Requested Outcome

Extend Duplicate Session into a destination submenu: keep In New Tab, list one Into Space #N item for every currently empty Space in the same tab, and provide Split Right and Split Down actions. Number only empty Spaces in visual tree order and show the matching Space #N label inside each empty placeholder so users can identify the destination.

## Project Impact

The terminal Space context menu changes from a direct **Duplicate Session** action to a dynamically populated submenu. The existing duplicate launch semantics remain authoritative: local sessions reuse non-secret launch metadata and live cwd where available; SSH sessions prefill non-secret connection metadata, prompt for authentication again, and request the live cwd where available.

`oneterm-terminal-view` owns destination discovery, SpaceId-derived labels, placeholder labels, split creation, destination validation, and filling a selected Space. The SSH authentication flow crosses the existing `terminal-view` → `state` command registry → `session-ui`/app composition boundary, so an SSH duplicate must retain its selected destination through authentication without retaining credentials. No persisted schema changes are requested; the user-facing number is the Space's existing monotonic, non-reused `SpaceId` value.

## Architecture and Boundary Questions

- Runtime and owning boundary: `TerminalPanel` and `SpaceTree` own same-tab destinations. The menu captures a stable `SpaceId` for each destination rather than using the visible number as identity. Cross-feature SSH dialog wiring continues through `WorkspaceCommands`; no new feature-to-feature dependency is allowed.
- Data ownership and lifecycle: `Space #N` uses `SpaceId(N)` directly. `SpaceId(0)` is reserved for the tab's initial terminal; user-visible empty Spaces are created by split with monotonic IDs starting at 1 (the spawn-failure empty recovery path also starts at 1). IDs are not reused during the tab lifetime or persisted. A destination is valid only while its tab and leaf exist and the leaf remains empty.
- Auth, security, privacy, or audit: unchanged from IN-0003 and DEC-0002. SSH passwords and key passphrases are neither retained nor prefilled. Destination metadata must contain no secret material.
- External systems and side effects: local selection spawns a new PTY; SSH selection authenticates and opens a new network session. The source session remains unchanged. A destination must not be occupied, replaced, or silently redirected if it becomes stale.
- Public interfaces and compatibility: no persisted or external public contract changes. The existing Duplicate Session keybinding continues to mean **In New Tab**, preserving current keyboard behavior. Internal duplicate commands may need a destination value that can represent new tab, existing empty Space, split right, or split down.

## Open Decisions and Questions

- [x] Product decision accepted: submenu order is **In New Tab**, zero-or-more **Into Space #N** items, separator, **Split Right**, **Split Down**.
- [x] Product decision accepted: only empty Spaces display their raw `SpaceId` as `#N`. `SpaceId(0)` belongs to the initial terminal and is not an empty destination; split-created empty Spaces start at `SpaceId(1)`. Because IDs are monotonic and non-reused, filling or closing another Space does not compact surviving labels (for example, after filling `Space #1`, `Space #2` remains `#2`). Menu items remain listed in current visual tree order.
- [x] Product decision accepted: empty destinations are omitted rather than shown disabled when none exist.
- [x] Compatibility decision accepted: the existing Duplicate Session action/keybinding keeps its current **In New Tab** behavior.
- [x] Safety behavior: revalidate the captured tab/`SpaceId` before filling it; if it no longer exists or is no longer empty, leave all sessions/layout unchanged and notify the user rather than selecting another destination.
- [ ] Non-blocking implementation check: confirm the vendored gpui-component menu API supports nested dynamic submenus. If it does not, stop before implementation and propose the smallest equivalent interaction for user approval.
