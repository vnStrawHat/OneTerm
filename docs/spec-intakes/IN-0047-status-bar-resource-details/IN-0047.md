# Spec Intake: status bar resource details

Date: 2026-09-28
Type: new_spec
Lane: normal

## Source

Owner request, 2026-09-28: "show more detail about the OneTerm process's CPU and Memory
when hovering the CPU/MEMORY item in the status bar." `US-0137` (IN-0045) had decided
against a tooltip because `StatusText` had no custom tooltip; the owner now asks for one.

## Requested Outcome

Hovering the status bar's CPU/MEM item shows a small table that answers "what is this
process using": the memory figures Task Manager offers (private working set, working set,
commit, peak working set; RSS and virtual size on Linux and macOS), the CPU figure with its
denominator (logical cores), total CPU time, thread count and process uptime. The item's own
text (`CPU 1.2%  MEM 49.3 MB`) does not change.

## Project Impact

- Surface: the status bar CPU/MEM item (`crates/workspace/src/widgets/resource.rs`) and the
  shared status-bar label widget (`crates/workspace/src/widgets/status_text.rs`), which
  gains an optional hover table.
- No persisted data, no public contract, no new dependency. One extra process snapshot
  (`CreateToolhelp32Snapshot`) per 2 s sample on Windows for the thread count; the whole
  sample (this snapshot plus the `sysinfo` refresh) runs on the background executor, not
  the UI thread (F1, 2026-09-28 acceptance rework).
- Owning doc: `docs/gui-layout.md` § Status bar.

## Candidate Work Packets

- [x] [`US-0148`](US-0148-resource-tooltip.md) — the hover table on the CPU/MEM item. No
  dependencies.

Follow-up candidates (not created):

- Shells line, "N local shells, X MB private working set". The shell pids live inside
  `oneterm-local-shell`'s event loop (`crates/local-shell/src/event_loop.rs`,
  `pty.child_pid()`) and are not exposed to the workspace; summing them needs a pid
  accessor through the terminal crates plus an `OpenProcess` per child each sample. More
  than a few lines, so left out.
- User vs kernel CPU time. `sysinfo` 0.37 exposes only their sum
  (`accumulated_cpu_time`); the split needs `GetProcessTimes` on Windows and
  `/proc/self/stat` on Linux.

Delivered, not a follow-up: a tooltip that refreshes while open was listed here as a
follow-up candidate at first ("the kit's tooltip builds its view once per hover") but the
owner rejected that limitation on acceptance (2026-09-28) — see `US-0148`'s "Acceptance
rework" section. The table now tracks the item's own 2 s cadence via a nested entity
(`DetailsTooltip` in `status_text.rs`) that observes the indicator, in place of the
`Vec<Section>` snapshot the first cut baked into the tooltip's builder closure.

## Architecture and Boundary Questions

- Runtime and owning boundary: the existing 2 s sampler in `resource.rs`; no new timer.
- Data ownership and lifecycle: the figures are held next to the label in the
  `StatusText` entity and replaced every sample.
- Auth, security, privacy, or audit: none. Only the own process is read.
- External systems and side effects: none.
- Public interfaces and compatibility: none (`oneterm-workspace` internals).
