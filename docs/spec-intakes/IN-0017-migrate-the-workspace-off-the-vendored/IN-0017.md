# Spec Intake: Migrate to gpui-component 0.6.0 (GPUI Kit) from crates.io

ID: IN-0017
Date: 2026-09-07
Type: maintenance
Lane: high_risk

## Requested Outcome

Migrate the workspace off the vendored `gpui-component` 0.5.2 fork (git rev `ea6b194d`, plus
`gpui` 0.2.2 from the `zed-industries/zed` monorepo) onto `gpui-component` 0.6.0 from crates.io,
which pulls `gpui-base` 0.6.0, `gpui-kit-assets` 0.6.0 and the `gpui-pre` 0.3.x GPUI family.

Keep every crate importing `gpui::` and `gpui_component::` by aliasing the packages in
`[workspace.dependencies]`; absorb the v0.6.0 dock redesign (`DockItem` → `DockLayout`,
`TabPanel` → `TabGroup`, the split `Panel` trait, the `DockSkin` renderer seam); retire the
vendor fork with its four patches and the `check-ui-fork` gate; and preserve the `docks.json`
layout schema across the upgrade.

The migration is intended to be invisible to users. Any visual or behavioral difference is a
defect of this work, not a feature of it.

## Project Impact

Measured against the current tree, not estimated:

- **Dependency graph** — 4 declarations replaced by 5; 11 crates depend on `gpui-component`;
  107 files import `gpui_component`. Package aliasing keeps all 107 import sites unchanged.
- **Workspace shell (largest surface)** — 46 `gpui_component::dock` references across 28 files.
  `DockItem` and `TabPanel`/`StackPanel` no longer exist; the `Panel` trait is split in two; a
  `DockArea` needs a `DockSkin` to draw any chrome.
- **Panel crates** — 5 `Panel` impls and 5 `register_panel` builders (agent-ui, app/ssh_client_panel,
  session-ui, sftp-ui, terminal-view).
- **Terminal split / Spaces** — drag payloads and close policy keyed on `TabPanel`.
- **Settings UI** — 10 `RenderOptions` field reads become accessor calls; the settings-section
  scroll fix must move from the vendor patch into OneTerm code.
- **Crash-report dialog** — the one multiline input moves to `Textarea`.
- **GPUI itself** — from `gpui` 0.2.2 (zed rev `1d217ee3`) to the `gpui-pre` 0.3.x family
  (snapshot `zed@5b055fa`); the API drift between those points is unmeasured.
- **Users** — the intended user-visible impact is zero. The risk is the opposite: a saved
  `docks.json` failing to load would silently reset a user's workspace.
- **Build and CI** — one CI step and one script are removed; `THIRD-PARTY-NOTICES.md`, `deny.toml`
  and `verify-dependency-graph.py` absorb a materially different crate set; Cargo profile overrides
  must be renamed to the new package names or GPUI silently drops to `opt-level = 0` in dev.
- **Agent guidance** — `reference/gpui-component` (pinned at 0.5.2) is the mandatory,
  web-search-preferred API source per `AGENTS.md` §3.2, and becomes actively misleading.

## Architecture and Boundary Questions

- Runtime and owning boundary: `crates/workspace` owns the `DockArea`, the skin, layout
  construction and persistence; `crates/state/src/dock_util.rs` owns tree traversal; feature crates
  own only their own panel impls. The v0.6.0 split adds a new boundary *inside* the dependency —
  behavior in `gpui_base::dock`, appearance in `gpui_component::dock` — which OneTerm now sits
  across rather than above.
- Data ownership and lifecycle: `oneterm_state::dock_persistence` remains the single read/update
  API for `docks.json`. It owns `schema_version`, `zoomed_panel` and `sftp_table_state` and
  flattens the upstream-owned `DockAreaState` fields. Nothing else patches that file.
- Auth, security, privacy, or audit: no auth or secret surface changes. The security-relevant
  change is supply chain: GPUI now arrives via `gpui-pre`, a republish by the gpui-kit maintainer
  rather than by Zed. Addressed in DEC-0006 with a stated rollback path.
- External systems and side effects: none at runtime. Build-time, the workspace stops cloning two
  git repositories and starts resolving five crates.io packages.
- Public interfaces and compatibility: `docks.json` is the only user-facing contract that can
  break, and the only one that can break *silently*. It gets its own high-risk packet (US-0042)
  with a fixture captured from the pre-migration build.
