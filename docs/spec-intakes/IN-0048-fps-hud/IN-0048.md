## Source

Owner request, 2026-09-29: "I also want a function to show FPS when needed. Default off.
Displayed information: max fps, frame, p95, drop, GPU name, GPU % usage", pointing at GPUI
Kit's `crates/fps` (published as `gpui-fps` 0.7.0; the pinned copy under
`reference/gpui-kit/crates/fps/` is byte-identical to the crates.io package once line endings
are normalised, checked 2026-09-29). Owner addition the same day: the HUD also shows the
**graphics API** in use, read at runtime where it can be, otherwise the compile-time backend
name, said so.

**Owner acceptance ruling, 2026-09-29** (supersedes the field list above): the HUD shows
**only** FPS, the GPU name, the graphics API and GPU % usage, and must **not** depend on
`gpui-fps` — its `profiler` feature costs +4 MB and +55-65 ns per task run with the HUD off
(`evidence/US-0151-verify.md` F1). Clicks and drags on the HUD must not reach the terminal
(F4). Reworked under `US-0151` § Acceptance rework.

## Requested Outcome

A performance overlay, off by default, that the user switches on when needed (settings switch,
app-menu entry, rebindable action). While on it shows, in a window corner: the frames the
window draws per second, the GPU's name, the graphics API and this process' GPU usage. While
off it costs nothing at run time: no timer, no counter, no PDH query, no dependency or gpui
feature added for it.

## Project Impact

- Surface: a new overlay on the main window (`OneTermWorkspace` root), a switch on the
  Settings **General** page (Interface group), an item in the app menu, a row in
  Settings > Key Bindings (App Menu group, unbound).
- Persisted data: one new optional field `show_fps` in `ui_config.json` (absent = `false`;
  no schema-version bump, old files load unchanged).
- No new dependency (the first cut's `gpui-fps` was removed on the owner's ruling). One more
  `windows-sys` feature, `Win32_System_Performance`, for the PDH GPU counter.
- Owning docs: `docs/gui-layout.md` (overlay + settings page), `docs/agents/persistence.md`
  (`ui_config.json` row), `docs/agents/dependencies.md` (§ 3 Windows FFI row).

Follow-up candidates (not created):

  `pub(crate)`, so OneTerm can read neither. Showing it needs a gpui accessor upstream, or a

## Architecture and Boundary Questions

- Runtime and owning boundary: `oneterm-workspace` (shell) renders the overlay at its root;
  the flag lives in `oneterm-settings`' `UiConfig`; the action in `oneterm-actions`.
- Data ownership and lifecycle: the flag is persisted in `ui_config.json`. The HUD entity (its
  ticker and PDH query) is created on the first frame the HUD is shown and dropped on the first
  frame it is hidden.
- Auth, security, privacy, or audit: none; only this process is measured.
- External systems and side effects: a PDH counter query (Windows), only while the HUD is shown.
- Public interfaces and compatibility: a new optional JSON field; old files load.
